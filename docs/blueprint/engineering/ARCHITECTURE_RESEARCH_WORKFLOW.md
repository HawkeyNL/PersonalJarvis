# Architecture Research Workflow

Mandatory for new subsystems, public APIs, persistence models, providers, security boundaries, major refactors, distributed components and performance-critical or financial paths.

## Required output

- problem statement and non-goals;
- current architecture and constraints;
- relevant prior ADRs/incidents;
- at least two viable design alternatives;
- pattern comparison;
- future-expansion analysis;
- security and failure analysis;
- decision matrix;
- selected design and rejected alternatives;
- migration, rollout and rollback;
- test and observability plan.

Patterns are selected only when they solve a documented problem, not because they are fashionable.
